    How it works
    
One config. Five things it does for you.

    


      

        

          
i.

          
Say why you hold each field.

          
Purposes, their legal basis and how long you keep the data live in one file. Purposes are typed, so a misspelt one is an error in your editor, and the audit catches the rest.

          The config, field by field →
        


// dpdp.config.ts
import { defineConfig } from "dpdp-kit";

export default defineConfig({
  fiduciary: { name: "Acme Pvt Ltd", grievanceUrl: "https://acme.in/grievance" },
  purposes: {
    account:       { basis: "legitimate-use", retain: "while-active" },
    marketing_sms: { basis: "consent", retain: { afterWithdrawal: "0d" } },
  },
  data: {
    users: {
      table: "users",
      subject: "id",
      fields: { phone: { category: "contact", purposes: ["account", "marketing_sms"] } },
    },
  },
  minimumRetention: "1y", // Rule 8(3)
});

      


      

        

          
ii.

          
Consent you can prove.

          
Section 6(10) puts the burden of proof on you. Every grant and withdrawal is stored with the notice version, language and channel, in a per-person SHA-256 hash chain.

          
verify() catches an edited, deleted or reordered event.

          How the record works →
        


await dpdp.consent.grant(userId, ["marketing_sms"], {
  noticeVersion: "2026-11",
  language: "hi",      // English or any of the 22 Eighth Schedule languages
  channel: "android",
});

await dpdp.consent.has(userId, "marketing_sms"); // true
await dpdp.consent.verify(userId);               // { ok: true, events: 1 }

      


      

        

          
iii.

          
Erasure that actually happens.

          
    
            
  • Processors are told to stop straight away.
    • 
            
  • A field is erased only when none of its purposes remain.
    • 
            
  • Rule 8(3)'s one-year minimum is respected.
    • 
            
  • Legal holds win: GST invoices wait 8 years, then get anonymised.
    • 
            
  • Safe with several servers: tasks are claimed atomically.
    • 
          

          Erasure and retention →
        


// a withdrawal schedules the erasure as dated tasks
await dpdp.consent.withdraw(userId, ["marketing_sms"]);

// an account deletion, with legal holds applied
await dpdp.erasure.deleteAccount(userId);

// then, from a daily cron:
const report = await dpdp.retention.run(); // { done, failed, manual }

      


      

        

          
iv.

          
Rights requests, on a clock.

          
Access, correction, erasure, grievance and nomination requests (Sections 11–14) are recorded with a due date. Grievances default to the 90 days of Rule 14(3).

          Rights requests →
        


const request = await dpdp.rights.open(userId, "grievance", {
  text: "I keep getting promo SMS",
}); // due in 90 days

await dpdp.rights.list({ overdue: true }); // your inbox of late answers
await dpdp.rights.summary(userId);         // Section 11: what you hold and why

      


      

        

          
v.

          
A GitHub Action that comments where it hurts.

          
Each problem lands on the pull request as an annotation, with a summary on the run page and errors / warnings outputs.

          Set it up →
        


# .github/workflows/dpdp.yml
on: [pull_request]
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - uses: yogesh2902/dpdp-kit@main
        with:
          schema: src/db/schema.ts

      

    

  






  

    Node-native
    
A library, not a service.

    
dpdp-kit runs inside your Node.js process. Personal data never leaves your infrastructure.

    

      
No server
Nothing to deploy, no sidecar to keep running, no REST API between your code and your consent records.

      
No account
No API key and no network calls. Install it from npm and it works offline.

      
Your Postgres
Records go into your own database through the Drizzle setup you already have: node-postgres, postgres.js, Neon or PGlite.

      
Your stack
Typed config, Express and Hono middleware, a CLI for CI. ESM, require() and TypeScript.
